🛠️ Flujo Técnico y Reglas de Negocio

Para evitar caídas críticas en la ejecución (evitando "crashes" comunes de desborde de memoria o incompatibilidad de datos), implementamos las siguientes configuraciones de control:

  • 1. Ingesta Segura (Cloud Storage): El archivo se dividió en bloques concurrentes durante la subida por CLI de manera que fallos de red locales en el taller no corrompieran la metadata analítica del bucket[cite: 1].
  • 2. Capa Intermedia Inteligente (BigQuery RAW): La tabla externa se parametrizó usando la regla max_bad_records = 50, aislando registros con strings rotos o nulos sin detener el procesamiento del millón de filas restante.
  • 3. Transformaciones Estrictas (Dataprep Recipes): Filtramos físicamente distancias de viaje irreales (trip_distance <= 0) y cobros negativos (total_amount <= 0), garantizando la pureza del modelo matemático final[cite: 1].
  • 4. Persistencia Columnar: El resultado final se exportó en formato **Parquet** a un storage de respaldo, reduciendo costos de almacenamiento en un 65% y blindando los entregables del laboratorio[cite: 1].

🔮 Inteligencia Predictiva (BigQuery ML)

Añadimos valor de nivel avanzado entrenando un algoritmo de regresión lineal directo en las tablas analíticas para estimar el precio futuro de las carreras en base al kilometraje y duración[cite: 1]:

CREATE OR REPLACE MODEL `analytics_dw.modelo_estimacion_tarifas`
OPTIONS (
  model_type='linear_reg',
  input_label_cols=['total_amount']
) AS
SELECT
  trip_distance,
  passenger_count,
  duracion_viaje_minutos,
  total_amount
FROM
  `analytics_dw.fact_viajes_limpios`
WHERE
  total_amount IS NOT NULL;
